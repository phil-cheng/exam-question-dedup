# 试题相似查重工具 — 需求说明

> 状态：已实测定案（2026-08-14：判决取消混合、纯余弦；阈值 0.75）  
> 配套文档：[自研 vs seekdb 对比分析](./方案对比-自研与seekdb.md) · [为何混合 embedding 与 BM25](./为何混合embedding与BM25.md)

---

## 1. 要解决什么问题

对用户当场指定的一份 Excel 试题表做**近重复查重**：找出「换了说法、但仍是同一道题」的题对，供人工确认后清洗。

不是组卷替换，不是持久题库检索，也不是「底库 + 新题」增量比对。

---

## 2. 输入

- 当前目录样例：`test.xls`（旧版 BIFF，需 `xlrd`；导出用 `xlsx`）
- 有效工作表：`正式题目`
- 表头在第 3 行（0-based 第 2 行），数据从第 4 行起
- 关键列：

| 列 | 用途 |
|---|---|
| 编号 | 结果展示 / 导出主键 |
| 题型 | 仅展示，**不作为查重硬过滤** |
| 试题内容 | 检索文本 |
| 候选项 A–F | 非空选项拼入检索文本 |
| 答案 | **不参与**查重（同一题改过答案仍应被查出） |
| 模块 / 课程 / 知识点 | 不参与计算，可作展示 |

检索文本：

```
试题内容 + 非空候选项A–F
```

题型不限制：单选改多选、判断改单选，只要题干+选项足够像，仍算疑似重复。

---

## 3. 使用方式

1. 打开 exe，选择一份 xls/xlsx
2. 可选：填写远程 embedding 服务（Ollama 或 vLLM）
3. 点「开始查重」，看进度
4. 用**阈值滑条**现场收紧 / 放宽，列表即时刷新
5. 导出当前阈值下的结果

约束：

- **不持久化 Excel 内试题**。换文件或关程序，内存丢掉。
- 服务地址、模型名可写在 exe 旁 `config.json`（这是配置，不是题库）。

---

## 4. 输出

导出**超过当前阈值的题对**，不是去重后的单题列表（否则一对里该留哪条说不清）。

建议字段：

- 编号 A、编号 B
- 相似度分数（0~1）
- 两侧题干摘要
- 可选：两侧题型、选项摘要

界面主视图与导出一致：题对列表。阈值改了只过滤，不重算。

---

## 5. 检索要求

| 项 | 要求 |
|---|---|
| 词法 | BM25，必开 |
| 语义 | 远程 embedding，可选 |
| 无模型时 | 自动回退纯 BM25，界面提示 |
| 联合方式 | 两路召回候选取并集；**判决只走一路**：有向量纯余弦，无向量 BM25 相对分（实测混合减分，已取消，见「为何混合」§6） |
| 给用户看的分 | 0~1，方便滑条。有向量：余弦；无向量：BM25 相对分（该题对自己为 1.0） |
| 默认阈值 | 0.75（按 Qwen3-Embedding-8B 实测校准，9/9 命中）；0.6b 用户建议降到 0.60~0.65 |
| 改阈值 | **禁止**重新分词 / 重新请求模型 / 重新两两比较 |

候选生成：每题 BM25 Top50 ∪ 向量 Top50，去掉自己。分数全部留在内存，滑条只做过滤。

---

## 6. 运行与打包

1. **单文件 exe**，依赖打进去，拷走就能用（Windows）。
2. **不打包** embedding 模型。只带 HTTP 客户端，对接用户自己的 Ollama / vLLM。
3. 协议优先 OpenAI 兼容 `POST /v1/embeddings`（vLLM 原生；Ollama 开兼容也能用）。可再兼容 Ollama 原生 `/api/embed`。
4. 万级（约 1 万题）内存应在百兆以内，不引入向量数据库。
5. 万级时用户可感知的等待应主要来自**远程向量化**，本地 BM25 + 余弦应在数秒内完成。

---

## 7. 规模与性能预期（已在本机测过）

768 维 float32，分块精确余弦 + 每题 Top50：

| 题量 | 向量内存 | Top50 结果 | 耗时 |
|---|---|---|---|
| 1,000 | 3 MB | 0.4 MB | 0.01 s |
| 5,000 | 15 MB | 2 MB | 0.24 s |
| 10,000 | 31 MB | 4 MB | 1.3 s |
| 30,000 | 92 MB | 12 MB | 5.7 s |

1 万题粗算：

```
读表 + 分词 + BM25     < 5 s
远程 embedding         1～10 min   ← 唯一大头（批量 32～64/批 + 进度条）
余弦 Top50             ~1.3 s
收集候选并集           < 0.01 s
滑条改阈值             即时
```

## 8. 技术选型（已拍板）

| 层 | 选型 | 不选 |
|---|---|---|
| 语言 / 打包 | Python + PyInstaller onefile | 不把 torch / 模型打进包 |
| 界面 | CustomTkinter | 不做本地浏览器套壳 |
| 读 xls | xlrd；导出 openpyxl | — |
| BM25 | `bm25s` + 汉字 2-gram / 3-gram | 第一期不打 jieba 词库 |
| 向量 | 内存 numpy 矩阵，精确余弦 | FAISS / Chroma / ES / seekdb |
| 判定 | 有向量纯余弦，无向量 BM25 归一化（不混合） | 不加权融合 / RRF |
| 存储 | 进程内；配置可落盘 | 不落试题、不建题库 |

---

## 9. 明确不做

- 不把 embedding 模型打进 exe
- 不上向量数据库 / 搜索引擎
- 不持久化题库
- 不用题型、知识点、答案做硬过滤（答案连检索文本都不进）
- 阈值不参与一次计算，只过滤已算好的候选对
- 第一期不做题库内部之外的「底库 vs 新文件」双文件比对

---

## 10. 界面四块

1. 选择 xls / xlsx
2. 可选：Base URL + 模型名（例：`http://127.0.0.1:11434/v1` + `bge-m3`）
3. 进度条 → 题对表 + 阈值滑条（即时刷新条数）
4. 导出当前结果为 xlsx

---

## 11. 后续可再开的口子（非本期）

- 题库内部自查以外的「底库 + 新题」增量查重
- 重复组（连通分量）视图
- 到 10 万+ 仍要精确互查时，把余弦实现换成 ANN，接口保持 `topk(vectors, k)`
- 若产品变成常驻题库服务，再评估 seekdb 等引擎（见对比文档）
