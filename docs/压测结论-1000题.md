# 1000 题压测结论

> 状态：已实测（2026-08-17）  
> 配套：[需求说明](./需求.md) · [如何选择 embedding 模型](./如何选择embedding模型.md) · [为何把混合方案改成BM25托底](./为何把混合方案改成BM25托底.md)  
> 原始数字：`data-validation/stress/stress_1000_report.json`

对打包后实际使用的语义路径（硅基流动 `Qwen/Qwen3-Embedding-8B`）和未配向量时的 BM25 托底，各跑一遍 1000 题，看三件事：能不能跑完、花多久、吃多少本机资源。顺带用 80 对埋点近重复核对召回。

---

## 1. 结论

| 问题 | 答案 |
|---|---|
| 1000 题查重能否完成 | **能。** 两条路径都正常结束，无超时、无 OOM |
| 谁慢 | **远程向量。** 86.3 s 墙钟里 86.0 s 在打 API |
| 本机算力够不够 | **够。** BM25 全程 0.44 s；余弦 Top50 仅 0.09 s |
| 本机内存 | BM25 峰值 **71.5 MB**；语义路径峰值 **252.5 MB**（解析 API JSON 时），算完约 150 MB |
| BM25 托底是否可用 | **字面近重复可用，换说法基本不行**（20 对换说法只召回 2 对） |
| 语义路径质量 | 默认阈值 0.75 下，80 对埋点 **全中** |

默认阈值 0.75 下「命中对数」BM25 7552、余弦 9716，**不能当成生产误报率**。见 §5。

## 3. 耗时与资源

| 路径 | 墙钟 | 本机 CPU 时间 | 峰值 RSS | 平均 CPU | 候选对（Top50 去重） |
|---|---:|---:|---:|---:|---:|
| BM25 托底 | 0.44 s | 0.42 s | 71.5 MB | 91% | 34407 |
| 语义余弦 | 86.3 s | 2.94 s | 252.5 MB | 3% | 35433 |

分阶段：

| 阶段 | BM25 | 语义 |
|---|---:|---:|
| 读 Excel | 0.12 s | 0.12 s |
| 核心计算 | 分词 + 建索引 + 检索 0.27 s | 远程向量 86.0 s |
| 精确余弦 Top50 | — | 0.09 s |
| 算完后 RSS | 67 MB | 150 MB |

读法：

- 候选对 3.4 万～3.5 万是 Top50 召回池大小，不是「判定为重复」的数量。1000 题、每题 50 邻域、无向去重后，不对称时落在 2.5 万～5 万之间，本次正常。
- 语义路径本机 CPU 只用了 2.94 s，平均占用 3%：进程在等网络。
- 向量矩阵本身约 `1000 × 4096 × 4 B ≈ 16 MB`。峰值 253 MB 出在把 API 返回的 JSON 解成矩阵时，不是余弦乘法把内存打爆。
- 按本次 API 吞吐约 **11.6 题/秒** 外推：5000 题约 7 分钟，10000 题约 14 分钟，仍然卡在服务端，不卡本机 CPU / 内存。BM25 千题亚秒，万题仍应是秒～十几秒量级（未实测）。

## 5. 不要误读的数字

阈值 0.75 下 BM25 报 7552 对、余弦报 9716 对。这套压测卷为了凑满 1000 道，含大量「同一知识点的判断题 + 单选题」同构题族，词面和语义都会挤在一起，分数被抬高。

它只说明：**过滤器在 1000 题规模下能算完、滑条有东西可滤**。不能据此说「生产上 1000 道真题会冒出近万对重复」。真题卷知识点打散后，这个数字会低很多。质量请看 §4 的埋点召回，不要看命中对数。

## 6. 环境坑：SOCKS 代理

本机同时有：

```
HTTP_PROXY=http://127.0.0.1:7892
ALL_PROXY=socks5://127.0.0.1:7892
```

`httpx` 看见 SOCKS 会要求 `socksio`。项目依赖和 PyInstaller 包都没带这个库，**exe 在该环境下会连不上向量服务**。压测清掉 `ALL_PROXY` / `all_proxy`、改走 HTTP 代理后，探测成功（维度 4096）。

若用户用 Clash 的 SOCKS 端口开 exe：改用 HTTP 代理端口，或以后把 `socksio` 打进包。
