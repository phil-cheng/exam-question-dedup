# Embedding 与 BM25：各自擅长什么，为何要混，为何更信语义

> 状态：已定案（2026-08-14：判决定案纯余弦、混合算分取消；66 题特征集实测见 §6）  
> 配套：[需求说明](./需求.md) · [自研 vs seekdb](./方案对比-自研与seekdb.md) · [如何选择 embedding 模型](./如何选择embedding模型.md)

本文只讨论**试题近重复查重**（同一份 Excel 内部互查）。  
「文本相似」指 BM25 这类基于词面重叠的检索；「语义相似」指 embedding 余弦。

---

## 1. 结论先说

| 问题 | 结论 |
|---|---|
| 为什么要混 | 两路漏的题不一样。并集召回，避免「只信一路」漏检。 |
| 混在哪 | **只在捞候选混（并集）**。判决已定案：有向量纯余弦，无向量纯 BM25。 |
| 为什么判决不混 | 实测掺 BM25 进判决对任何模型都是减分（见 §5、§6）。 |
| 不是什么 | 不是「模型越大、维度越多就能消灭 BM25」；0.7/0.3 不是最优、已彻底取消。 |

一句话：BM25 负责「别漏掉字面上就很像的题」（召回层）；embedding 负责「别漏掉换了说法的题」，并独占滑条上那个判定分。

---

## 2. 两种算法在比什么

**BM25**  
把题干+选项切成字 n-gram（本方案用 2-gram / 3-gram），按「词出现得勤不勤、这个词在全库稀不稀有、题有多长」打分。  
只看字面，不理解「动态数组」和「长度可变的顺序表」是不是一回事。

**Embedding**  
远程模型（Ollama / vLLM）把整段文本压成向量，用余弦比方向。  
训得好的中文相似度模型会让「意思近」的题靠在一起，即使用词不同。

两者量纲不同：BM25 是「相对这道题的词面相关」，余弦是「0~1 的方向相似度」。不能直接加，所以才有后面的「召回用并集、判决用语义」。

---

## 3. 各自擅长 / 不擅长

### 3.1 BM25

| 擅长 | 不擅长 |
|---|---|
| 改了个别词、选项换序、标点空格不同 | 整句换说法、同义改写 |
| 专有名词、国标号、协议名、公式碎片（稀有词 IDF 高） | 「意思一样但词几乎不重叠」 |
| 无模型、离线、稳定、极便宜 | 跨题的原始分不可比（题长短一变，分就漂） |
| 近重复里最常见的「几乎没改」 | 模板相同、考点不同时，词面分会虚高 |

典型能抓住：`Python中的列表(List)是一种动态数组。` vs 只改了标点或「动态数组」写成「动态的数组」。  
典型会漏：同一道题把「动态数组」改成「长度可以变化的顺序存储结构」。

### 3.2 Embedding

| 擅长 | 不擅长 |
|---|---|
| 换说法、同义改写、语序大变 | 模型弱 / 非中文 / 没见过这种题时，排序会飘 |
| 跨题的余弦大致可比（同一模型下） | 只差一个关键词、数字、年份时，池化容易把差别冲淡 |
| 给滑条一个直观的 0~1 | UDP vs TCP、GB/T 1234 vs 1235 可能都「像计算机题」 |
| 真重复几乎一定语义也近 | 不是「更大、更高维」就一定准；维度是上限不是精度 |

典型能抓住：题干改写、选项换了一种表述，人仍认为是同一题。  
典型会糊：两道「下列哪项是线性结构」选项几乎不同；或一道题只把「不包括」改成关键考点词。

参数量和维度**不能**推导出「已经覆盖 BM25」。覆盖词面近重复，靠的是模型在中文短问句上是否对齐过「是否同义」，不是向量有多长。

## 4. 为什么要混合

漏检比排序不好更致命：真重复没进候选，后面滑条再松也出不来。

最初假设两路盲区正交；实测（§6.3）是**包含关系**：BM25 能补的（字面重叠）余弦全都覆盖，BM25 的盲区（换说法）8B 余弦也覆盖。并集的价值因此不是「互补」，而是**便宜保险**：

```
只靠 BM25     → 换说法的真重复进不了 Top50（实测：一对 bm25=0.000、排名 51，见 §6）
只靠 embedding → 模型弱时余弦排序会飘，换说法对可能掉出 Top50
两路并集       → 只要有一路觉得像，就留下给后面打分；成本近零，留作兜底
```

本方案的混法（已经拍板）：

```
BM25 Top50  ──┐
              ├── 并集（召回，两路同等重要）
余弦 Top50  ──┘
                ↓
         每对一个判决分 s
                ↓
         滑条：s ≥ T 才显示 / 导出
```

混合解决的是**召回**，不是让用户调两个阈值。

BM25 成本极低（万级秒级），即使「多数真重复余弦已经够高」，留在并集里仍是便宜保险，专门补专有名词、数字、单点差异。

没有 embedding 服务时：并集退化成只有 BM25，判决分改用「相对自己的 BM25」（自己和自己 = 1.0）。这是降级，不是混合。

## 5. 为什么判决最终不混合（定案记录）

2026-08 实测后**彻底取消混合算分**，代码已删。滑条只卡一个已经算好的 s：

```
有向量   s = 余弦
无向量   s = BM25 相对分（降级）
```

定案理由（保留过程论证）：

### 5.1 查重要判的是「是不是同一题」

同一题首先是意思同一。词面很像只是常见表象，不是定义。  
换说法的真重复：词面分低、余弦高 → 若判决掺 BM25，会被拉下线，漏检。  
同一模板、考点不同：词面分高、余弦往往没那么高 → 掺 BM25 会抬进线，误报。

判决掺词面，等于让滑条同时表示两件不完全同向的事，更难解释成「像不像」。

### 5.2 余弦适合当全库门槛，BM25 不适合

- 同一模型下，题 A 的 `0.91` 和题 B 的 `0.55` 可以放在同一把滑条上比。  
- BM25 是「相对这一题」的相关分，题长短、用词稀有度一变，跨题不能直接比。归一化能缓解，校准仍弱于余弦。

所以：词面算法放在**找得到**；语义分放在**卡得住、解释得清**。

### 5.3 实测：掺任何比例都是减分（不是调参问题）

66 题特征集实测（§6），9 对真重复的两种分数摆在一起算：

- 换说法对 bm25（0.000~0.390）远低于 cos（0.61~0.82），只要 bm25 < cos，混合分就小于纯 cos——掺入即精确打击「临界带」，把该过的对拖下线。
- 0.6B 模型 + α=0.7：0.7 阈值命中从纯 cos 的 **8/9 掉到 6/9**；8B 模型同样从 9/9 掉到 6/9。**任何模型、任何阈值下掺 BM25 都不如纯 cos。**
- BM25 高分的对（标点/选项重排/公式），余弦本来就 ≥0.98——掺了是冗余；BM25 低分的对（换说法），掺了是减分。BM25 对判决分的贡献恒 ≤ 0。

因此「模型弱就把 α 降到 0.8、0.7」的旧建议被推翻：**模型弱时应该降阈值**（0.6B 用 0.60~0.65 可 9/9，代价是误报多、靠人工筛），而不是掺 BM25。

RRF 不用分数、只用名次，每题都有「第 1 名」，不适合当「够不够像」的全局阈值，故不采用。

## 6. 实测验证（2026-08，66 题特征集）

数据集 `data-validation/test_dataset.xlsx`：含「换说法型（词面不重叠、考点同）」「只差一字/数字」「模板撞车」「符号公式」等形态，人工标注 9 对真重复、9 对灰色。同一批题分别用 **BM25 自归一化分**（自己对自己 = 1.0）和 **Qwen3-Embedding-8B 余弦**当判定器。全量分数已落盘 `data-validation/scores.csv`（含标注列），本节的数字均可由它复算，不必重调 API。

### 6.1 真重复 9 对：两把尺子各打多少分

| 真重复对 | 形态 | BM25 分 | 余弦 8B | BM25 排名 | 余弦排名 |
|---|---|---|---|---|---|
| 0101-0102 | 标点/空白 | **1.000** | 0.994 | 1 | 2 |
| 0101-0103 | 标点/空白 | **1.000** | 0.988 | 2 | 3 |
| 0102-0103 | 标点/空白 | **1.000** | 0.982 | 1 | 3 |
| 0601-0602 | 选项重排 | **1.000** | 0.993 | 2 | 2 |
| 0701-0702 | 符号公式 | 0.944 | 0.981 | 1 | 1 |
| 0703-0704 | 符号公式 | 0.903 | 0.985 | 1 | 1 |
| 0301-0302 | 换说法 | 0.349 | 0.777 | 8 | 2 |
| 0303-0304 | 换说法 | **0.000** | 0.792 | **51** | 1 |
| 0305-0306 | 换说法 | 0.390 | 0.823 | 1 | 1 |

### 6.2 各阈值命中率（真重复命中 / 灰色可见 / 误报）

| 阈值 | BM25 全量 | BM25 Top50 | 余弦 8B 全量 |
|---|---|---|---|
| 0.3 | 8/9/60 | 8/9/60 | 9/9/1415 |
| 0.4 | 6/8/43 | 6/8/43 | 9/9/623 |
| 0.5 | 6/8/26 | 6/8/26 | 9/9/276 |
| 0.6 | 6/8/16 | 6/8/16 | 9/9/114 |
| 0.7 | 6/6/15 | 6/6/15 | **9/9/41** |
| 0.8 | 6/5/9 | 6/5/9 | 7/8/16 |

### 6.3 实测结论

1. **识别率差距 = 3 对换说法。** BM25 在可用工作点（0.5~0.7）稳定 6/9；8B 余弦 0.7 阈值 9/9。BM25 唯一一次 8/9 出现在 0.3 阈值，误报 60 个，实际不可用。
2. **BM25 输的形态高度集中——全是字面不重叠的换说法。** 最极端的一对（「栈先进后出」vs「后放入的先取出」）BM25 给 **0.000 分、排名 51**，连 Top50 召回都进不去，召回层和判定层双重漏检，调阈值救不回来。这是结构性的，不是参数问题。
3. **词面重叠的形态 BM25 不输余弦**：标点、选项重排、符号公式 6 对全部 ≥0.90，与余弦几乎并列。但 BM25 擅长的是余弦早就满分的部分——它补不上余弦漏掉的任何一对，余弦却覆盖它的盲区。
4. **BM25 全量 = Top50**：两列数字完全一样，说明召回层没有额外损失，损失全在判定能力上。

实测印证了本文的拍板：**并集召回保留 BM25 当便宜保险；判决用纯余弦。** 若判决掺入 BM25（α<1），换说法对的分数只会被 0.0~0.39 的词面分往下拖，补不回任何余弦漏掉的东西。

## 7. 和界面怎么对应

| 用户看到的 | 系统实际 |
|---|---|
| 一个滑条「相似度 ≥ xx%」 | 卡判决分 s |
| 有模型 | s = 余弦（语义） |
| 没模型 | s = BM25 相对分（词面），并提示已降级 |
| 用户调不了的 | 两路 Top50、并集（混合算分已取消，无 α） |

用户在调「多像才算重复」，不是在调「BM25 占多少」。

---

## 8. 记住这三句

1. **BM25 找字面近的；embedding 找意思近的。** 盲区不同，所以要混。  
2. **混在召回（并集），不要混成两个阈值。**  
3. **滑条只看语义分**，因为查重判的是是不是同一题，且余弦才能当一把尺。词面分留在召回层当保险、无向量时兜底判定，**永不与余弦混合**。
