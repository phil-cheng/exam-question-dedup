# Embedding 与 BM25：各自擅长什么，为何要混，为何更信语义

> 状态：与当前方案对齐（2026-03-25）  
> 配套：[需求说明](./需求.md) · [自研 vs seekdb](./方案对比-自研与seekdb.md)

本文只讨论**试题近重复查重**（同一份 Excel 内部互查）。  
「文本相似」指 BM25 这类基于词面重叠的检索；「语义相似」指 embedding 余弦。

---

## 1. 结论先说

| 问题 | 结论 |
|---|---|
| 为什么要混 | 两路漏的题不一样。并集召回，避免「只信一路」漏检。 |
| 混在哪 | **捞候选**必须两路都上；**滑条卡的分**有向量时以语义为主（默认纯余弦）。 |
| 为什么语义比例更高 | 查重要判的是「还是不是同一道题」，这首先是意思问题。词面分适合找候选，不适合当全库统一门槛。 |
| 不是什么 | 不是「模型越大、维度越多就能消灭 BM25」。也不是 0.7/0.3 已经最优。 |

一句话：BM25 负责「别漏掉字面上就很像的题」；embedding 负责「别漏掉换了说法的题」，并提供滑条上那个更好解释的分。

---

## 2. 两种算法在比什么

**BM25**  
把题干+选项切成字 n-gram（本方案用 2-gram / 3-gram），按「词出现得勤不勤、这个词在全库稀不稀有、题有多长」打分。  
只看字面，不理解「动态数组」和「长度可变的顺序表」是不是一回事。

**Embedding**  
远程模型（Ollama / vLLM）把整段文本压成向量，用余弦比方向。  
训得好的中文相似度模型会让「意思近」的题靠在一起，即使用词不同。

两者量纲不同：BM25 是「相对这道题的词面相关」，余弦是「0~1 的方向相似度」。不能直接加，所以才有后面的「召回用并集、判决用语义」。

---

## 3. 各自擅长 / 不擅长

### 3.1 BM25

| 擅长 | 不擅长 |
|---|---|
| 改了个别词、选项换序、标点空格不同 | 整句换说法、同义改写 |
| 专有名词、国标号、协议名、公式碎片（稀有词 IDF 高） | 「意思一样但词几乎不重叠」 |
| 无模型、离线、稳定、极便宜 | 跨题的原始分不可比（题长短一变，分就漂） |
| 近重复里最常见的「几乎没改」 | 模板相同、考点不同时，词面分会虚高 |

典型能抓住：`Python中的列表(List)是一种动态数组。` vs 只改了标点或「动态数组」写成「动态的数组」。  
典型会漏：同一道题把「动态数组」改成「长度可以变化的顺序存储结构」。

### 3.2 Embedding

| 擅长 | 不擅长 |
|---|---|
| 换说法、同义改写、语序大变 | 模型弱 / 非中文 / 没见过这种题时，排序会飘 |
| 跨题的余弦大致可比（同一模型下） | 只差一个关键词、数字、年份时，池化容易把差别冲淡 |
| 给滑条一个直观的 0~1 | UDP vs TCP、GB/T 1234 vs 1235 可能都「像计算机题」 |
| 真重复几乎一定语义也近 | 不是「更大、更高维」就一定准；维度是上限不是精度 |

典型能抓住：题干改写、选项换了一种表述，人仍认为是同一题。  
典型会糊：两道「下列哪项是线性结构」选项几乎不同；或一道题只把「不包括」改成关键考点词。

参数量和维度**不能**推导出「已经覆盖 BM25」。覆盖词面近重复，靠的是模型在中文短问句上是否对齐过「是否同义」，不是向量有多长。

---

## 4. 为什么要混合

漏检比排序不好更致命：真重复没进候选，后面滑条再松也出不来。

两路的盲区几乎正交：

```
只靠 BM25     → 换说法的真重复进不了 Top50
只靠 embedding → 模型糊、或只差一个术语时，真重复可能排很后
两路并集       → 只要有一路觉得像，就留下给后面打分
```

本方案的混法（已经拍板）：

```
BM25 Top50  ──┐
              ├── 并集（召回，两路同等重要）
余弦 Top50  ──┘
                ↓
         每对一个判决分 s
                ↓
         滑条：s ≥ T 才显示 / 导出
```

混合解决的是**召回**，不是让用户调两个阈值。

BM25 成本极低（万级秒级），即使「多数真重复余弦已经够高」，留在并集里仍是便宜保险，专门补专有名词、数字、单点差异。

没有 embedding 服务时：并集退化成只有 BM25，判决分改用「相对自己的 BM25」（自己和自己 = 1.0）。这是降级，不是混合。

## 5. 为什么语义比例高于文本相似

这里的「比例高」指**判决分更信余弦**，不是滑条去调 7:3。

滑条只卡一个已经算好的 s。有向量时默认：

```
s = 余弦          （α = 1.0，第一期默认）
```

若以后做加权，也是语义占大头，例如 `0.7 * 余弦 + 0.3 * BM25归一化`。  
`0.7/0.3` 是「语义为主」的先验，**不是**在本仓库题上扫出来的最优解。

### 5.1 查重要判的是「是不是同一题」

同一题首先是意思同一。词面很像只是常见表象，不是定义。  
换说法的真重复：词面分低、余弦高 → 若判决掺太多 BM25，会被拉下线，漏检。  
同一模板、考点不同：词面分高、余弦往往没那么高 → 掺 BM25 会抬进线，误报。

判决掺词面，等于让滑条同时表示两件不完全同向的事，更难解释成「像不像」。

### 5.2 余弦适合当全库门槛，BM25 不适合

- 同一模型下，题 A 的 `0.91` 和题 B 的 `0.55` 可以放在同一把滑条上比。  
- BM25 是「相对这一题」的相关分，题长短、用词稀有度一变，跨题不能直接比。归一化能缓解，校准仍弱于余弦。

所以：词面算法放在**找得到**；语义分放在**卡得住、解释得清**。

### 5.3 为何不默认 0.7/0.3

更干净的默认是判决用纯余弦。理由见上：掺 0.3 词面既可能漏改写题，也可能放进模板题。  
只有确认远程模型偏弱（领域差、非中文、效果明显不稳）时，再把 α 降到 0.8、0.7，用标注题对看漏检/误报。没有标注之前，任何比例都只是先验。

RRF 不用分数、只用名次，每题都有「第 1 名」，不适合当「够不够像」的全局阈值，故不采用。

## 6. 和界面怎么对应

| 用户看到的 | 系统实际 |
|---|---|
| 一个滑条「相似度 ≥ xx%」 | 卡判决分 s |
| 有模型 | s = 余弦（语义） |
| 没模型 | s = BM25 相对分（词面），并提示已降级 |
| 用户调不了的 | 两路 Top50、并集、α（第一期写死为 1.0） |

用户在调「多像才算重复」，不是在调「BM25 占多少」。

---

## 7. 记住这三句

1. **BM25 找字面近的；embedding 找意思近的。** 盲区不同，所以要混。  
2. **混在召回（并集），不要混成两个阈值。**  
3. **滑条更信语义**，因为查重判的是是不是同一题，且余弦才能当一把尺。词面分留下当保险和离线兜底，不默认用来抬判决分。
