# 为何把混合方案（embedding + BM25）改成 BM25 托底

> 状态：已定案（2026-08-14 实测；2026-08-15 删除并集后定稿）  
> 配套：[需求说明](./需求.md) · [自研 vs seekdb](./方案对比-自研与seekdb.md) · [如何选择 embedding 模型](./如何选择embedding模型.md) · [为何给余弦加BM25提升不了结果](./为何给余弦加BM25提升不了结果.md)

一句话：**判决只看余弦；BM25 只在无向量服务时托底判定，有向量时不算它、也不与余弦混合。**

本文是决策变更记录：当初为什么想混合，实验如何证伪，最后定案成什么样。

---

## 1. 结论先说

| 项 | 原方案（已废弃） | 定案方案 |
|---|---|---|
| 候选召回 | BM25 Top50 ∪ 余弦 Top50 并集 | **余弦 Top50**（并集实测零贡献，已删） |
| 判定分 | `0.7·余弦 + 0.3·BM25归一化` | **纯余弦** |
| BM25 的位子 | 一半的判决分 | 无向量时托底判定（有向量时不算 BM25） |
| 模型弱时 | 把 α 降到 0.8 / 0.7 | **降阈值**（0.6B 用 0.60~0.65），不掺 BM25 |
| 默认阈值 | 0.82 | 0.75（按 8B 实测校准） |

---

## 2. 原始方案与假设

第一版设计里，判决分是加权融合：

```
s = 0.7 × 余弦 + 0.3 × BM25归一化
```

背后的假设是「两路盲区互补」：BM25 抓字面差异（专有名词、数字、单字不同），embedding 抓换说法；加权融合各取所长。直觉上成立——BM25 满分的对余弦也高、换说法对 BM25 低分，互补看起来正好。

**这个假设被实验证伪了（§3）。**

---

## 3. 实验证伪（66 题特征集）

数据集 `data-validation/test_dataset.xlsx`：含换说法型、只差一字/数字、模板撞车、符号公式等形态，人工标注 9 对真重复、9 对灰色。全量分数落盘 `data-validation/scores.csv`（含标注列），本文所有数字均可由它复算，不必重调 API。

### 3.1 判定对比：BM25 6/9 vs 8B 余弦 9/9

真重复 9 对，两把尺子各打多少分：

| 真重复对 | 形态 | BM25 分 | 余弦 8B | BM25 排名 | 余弦排名 |
|---|---|---|---|---|---|
| 0101-0102 | 标点/空白 | **1.000** | 0.994 | 1 | 2 |
| 0101-0103 | 标点/空白 | **1.000** | 0.988 | 2 | 3 |
| 0102-0103 | 标点/空白 | **1.000** | 0.982 | 1 | 3 |
| 0601-0602 | 选项重排 | **1.000** | 0.993 | 2 | 2 |
| 0701-0702 | 符号公式 | 0.944 | 0.981 | 1 | 1 |
| 0703-0704 | 符号公式 | 0.903 | 0.985 | 1 | 1 |
| 0301-0302 | 换说法 | 0.349 | 0.777 | 8 | 2 |
| 0303-0304 | 换说法 | **0.000** | 0.792 | **51** | 1 |
| 0305-0306 | 换说法 | 0.390 | 0.823 | 1 | 1 |

各阈值命中率（真重复命中 / 灰色可见 / 误报）：

| 阈值 | BM25 全量 | BM25 Top50 | 余弦 8B 全量 |
|---|---|---|---|
| 0.3 | 8/9/60 | 8/9/60 | 9/9/1415 |
| 0.4 | 6/8/43 | 6/8/43 | 9/9/623 |
| 0.5 | 6/8/26 | 6/8/26 | 9/9/276 |
| 0.6 | 6/8/16 | 6/8/16 | 9/9/114 |
| 0.7 | 6/6/15 | 6/6/15 | **9/9/41** |
| 0.8 | 6/5/9 | 6/5/9 | 7/8/16 |

三个事实：

1. **BM25 在可用工作点（0.5~0.7）稳定 6/9**；唯一一次 8/9 在 0.3 阈值、误报 60 个，实际不可用。8B 余弦 0.7 阈值 9/9。
2. **BM25 输的形态高度集中——全是字面不重叠的换说法。** 最极端的一对（「栈先进后出」vs「后放入的先取出」）给 0.000 分、排名 51，连自己的 Top50 都进不去，召回层和判定层双重漏检，调阈值救不回来。这是结构性的，不是参数问题。
3. **词面重叠的形态 BM25 不输余弦**（6 对 ≥0.90），但那是余弦早就满分的部分——BM25 补不上余弦漏掉的任何一对，余弦却覆盖它的盲区。

### 3.2 「盲区互补」被证伪：实际是包含关系

「BM25 抓字面、embedding 抓换说法、两者互补」的假设不成立：

- BM25 的强项（字面重叠）→ 余弦全覆盖（≥0.98）
- BM25 的盲区（换说法）→ 余弦的强项
- 余弦的盲区（弱模型时换说法对掉出线）→ BM25 同样给 0 分，帮不上

**BM25 的盲区包含余弦的盲区**，不是正交。0.6B 模型漏的 2 对恰好就是换说法对（cos 0.61、0.71），那两对的 BM25 分是 0.000 和 0.349——想托一把都没分可托。

### 3.3 掺入判决是减分，不是调参问题

数学上：只要 `bm25 < cos`，混合分就小于纯 cos。换说法对的 bm25（0~0.39）远低于 cos（0.61~0.82），掺入即精确打击「临界带」，把该过的对拖下线。

实测算账（α=0.7）：

- **0.6B 模型**：0.7 阈值命中从纯 cos 的 8/9 掉到 **6/9**
- **8B 模型**：0.75 阈值命中从 9/9 掉到 **6/9**（0.777 的换说法对被拖到 0.649）

BM25 高分的对余弦本来就 ≥0.98——掺了是冗余；BM25 低分的对掺了是减分。**BM25 对判决分的贡献恒 ≤ 0，任何模型、任何比例、任何阈值下掺入都不如纯 cos。** 因此「模型弱就把 α 降到 0.8、0.7」的旧建议也一并推翻：模型弱时降阈值，不是掺 BM25。

## 4. 定案方案

```
读表 → 尝试向量服务
        ├─ 成功      → 余弦 Top50 → 判决 s = 余弦
        └─ 失败/未配 → BM25 Top50 → 判决 s = BM25 相对分（UI 提示「已回退到 BM25」）
                ↓
         滑条：s ≥ T 才显示 / 导出
```

- **召回并集已删除**：实测并集零贡献（多捞的对 cos≤0.33，任何滑条位置都不可见），且 BM25 成功集 ⊆ 余弦高分集，救不了余弦漏的对。论证见 [为何给余弦加BM25提升不了结果](./为何给余弦加BM25提升不了结果.md) §2。
- **判决纯余弦**：实测任何掺入都是减分；余弦还是全库可比的同一把尺（BM25 是「相对这一题」的分，跨题不可比）。
- **托底**：没配服务或请求失败时才计算 BM25，用它的相对分做完整判定。这是降级不是混合；有向量服务时 BM25 一次都不被计算。
- **阈值**：默认 0.75（按 8B 校准，9/9 命中 + 误报 23）；0.6B 用户降到 0.60~0.65（可 9/9，误报多靠人工筛）。

---

## 5. 和界面怎么对应

| 用户看到的 | 系统实际 |
|---|---|
| 一个滑条「相似度 ≥ xx%」 | 卡判决分 s |
| 有模型 | s = 余弦（语义） |
| 没模型 | s = BM25 相对分（词面），并提示已降级 |
| 用户调不了的 | 余弦 Top50（或托底时的 BM25 Top50），无任何混合权重可调 |

用户在调「多像才算重复」，不是在调「BM25 占多少」。

---

## 6. 记住这三句

1. **判决只看语义分**：查重判的是「是不是同一题」，余弦才能当全库一把尺。  
2. **混合已被实测证伪**：掺 BM25 对任何模型、任何阈值都是减分——不是调参问题，是方向错误。  
3. **BM25 的位子**：只在无向量服务时托底判定，有向量时不算它，**永不与余弦混合**。
