# 为何不整段清洗检索文本

> 状态：已拍板，与实现一致  
> 配套：[需求说明](./需求.md) · [为何把混合方案改成 BM25 托底](./为何把混合方案改成BM25托底.md)

检索文本只有一份：`Question.search_text`，BM25 和 embedding 共用。  
本文记录：**为什么不用「去掉 A. + 删光标点/特殊字符后再计算」**。

---

## 1. 两种做法

**现在（采用）：**

```
题干.strip()
A.选项A
B.选项B
…
```

原文标点、问号、换行都保留。  
BM25 不吃整段，只吃 `tokenize()` 抽出来的英文整词和汉字 2/3-gram——标点本来就不会进词。  
embedding 吃上面这段「像人写的题」。

**曾设想、未采用：**

1. 题干 + 选项**正文**（不要 `A.` `B.`）  
2. 整段替换掉标点、空格、特殊字符  
3. 同一串再送去向量化和 BM25

---

## 2. 结论

普通文字近重复上，两套分差很小。  
一旦出现公式、复杂度、语言名、国标号，整段清洗更容易把该留下的符号洗坏。

所以维持现在：一份自然文本，分词层忽略标点，不为了几个 n-gram 去动符号。

---

## 3. 逐项比

### 3.1 要不要 `A.` `B.`

实现里**有**选项字母，不是漏了。

| | 保留 `A.`（现在） | 去掉字母 |
|---|---|---|
| 向量 | 几个字符，拉不动整题方向；题库语料里常见，有助于认出「后面是选项」 | 选项对调时余弦会略高一丁点 |
| BM25 | `a` `b` `c` IDF 很低，几乎不拉分 | 少几个无意义词，可忽略 |

查重里真重复通常连选项字母也一样，字母对余弦近乎常数。  
选项对调仍算同一题时，去掉字母会略友好，差在小数点后两位，不是现在的瓶颈。

### 3.2 标点还要不要先删

BM25 已经等价于「不算标点」：

- `动态数组` 和 `动态数组。` 词完全一样  
- 题干末尾 `？`、我们加的点、换行都抽不进词  
- 换行还避免 n-gram 从题干末尾粘到选项开头

向量对 `？`、换行几乎不敏感。模型训练时见到的就是带标点的题，洗得太干净收益很小。

整段删标点**唯一明显的好处**：汉字中间的顿号、空格会把词切开。

| 文本 | 现在的 BM25 | 先删掉顿号/空格 |
|---|---|---|
| `动态数组` | 动态 态数 数组 + 三字 | 同左 |
| `动态、数组` / `动态 数组` | 切开，少了 `态数` | 粘回 `动态数组`，略好 |

这是局部损失：一道 30 字的题，中间一个空格大约少 2 个二字、3 个三字，其余还在。  
正规试题很少在汉字中间插空格；偶发的是 Word/PPT 粘出来的全角空格。

### 3.3 特殊字符一律干掉——这里会输

| 原文 | 现在 | 整段删特殊字符 |
|---|---|---|
| `C++` / `C#` | 拉丁规则里 `+` `#` 本就不进词，剩下 `c` | 可能仍是 `C`，或和前后粘成怪词 |
| `O(n log n)` | `o` `n` `log` `n` | 可能变成 `Onlogn` |
| `GB/T 1234` | `gb` `t` `1234` | 可能 `GBT1234`，和另一种写法对不齐 |

试题里这类符号比「汉字中间空格」常见。整段清洗赢在顿号，输在符号题。查重要稳，不能为了粘回少数 n-gram 去赌公式。

---

## 4. 为什么两种算法共用一份原文

1. **稳**：少一层清洗规则（删什么、换成空还是删掉、公式怎么办）。  
2. **各吃各的**：BM25 靠分词忽略标点；向量吃自然文本，不必先洗成「不像题」的一长串。  
3. **`A.` 是结构不是噪声**：对向量略有利，对 BM25 可忽略。

若以后表里全角空格、顿号很多，只在 **`tokenize` 前**把汉字之间的空白/顿号压掉即可，不动 embedding，也不去掉 `A.`。那是加固，不是换流水线。本期不做。

---

## 5. 三句话

1. 文字近重复上，两种做法差不多。  
2. 「去 `A.` + 删光特殊字符」的风险大于收益，符号题会受伤。  
3. 现在的方案：保留选项字母和原文标点；标点交给分词丢掉，而不是先整段洗。
